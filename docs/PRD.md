## 1. 文档说明与决策边界

本文将已讨论的用户需求整理为可供设计和开发拆分的产品基线。用户尚未确认的实现方向、数值目标和功能取舍均属于本版建议，不代表已经完成用户验证。

| 类型 | 内容 |
| --- | --- |
| 已明确的用户痛点 | 日常工作和生活中不断出现新事项；当前任务频繁被打断；连续切换后遗忘早先未完成的任务 |
| 已讨论的核心方向 | 快速记录新事项、明确当前任务、暂停时保存断点、结束后恢复旧任务、每日收尾 |
| 本版范围建议 | 首版围绕个人桌面场景闭环，优先适配 Windows；本地保存；单人使用；不要求登录 |
| 待验证假设 | 用户愿意在切换时留下简短断点；恢复提示可以减少遗忘并降低重新进入工作的成本 |
| 尚未承诺 | 上线日期、开发工期、商业模式、其他平台支持时间、任何自动化或 AI 能力 |

优先级定义：P0 为本版 MVP 必须具备；P1 为后续候选，不构成本版验收门槛；P2 为远期探索。本文件不规定技术框架、数据库或代码结构。

## 2. 背景与问题定义

用户在处理任务 A 时收到任务 B，随后又进入任务 C、D。每次切换既需要判断先做什么，也需要记住上一件事情的进展。随着事项累积，用户可能忘记 A 尚未结束，即使记得，也需要重新查找日志、代码和沟通记录才能继续。

产品需要承接四类负担：

1. **记忆负担**：担心忘记新事项，必须不断在脑中重复记住。
2. **调度负担**：新出现的事项占据注意力，当前工作容易被动让位。
3. **恢复负担**：回到旧任务时，不清楚已经做过什么、下一步是什么。
4. **收尾负担**：一天结束后，不确定哪些事情仍悬而未决。

产品可以改善记录与恢复流程；团队持续插入紧急任务、工作量超载和优先级冲突仍需要协作机制处理，不作为本版产品能够独立解决的问题。

## 3. 目标用户与使用场景

### 3.1 核心用户

首要用户为主要在电脑上工作、经常收到临时请求的软件开发者。其工作可能同时涉及开发、排障、评审、沟通和等待他人反馈。

扩展用户包括存在类似切换负担的产品、设计、运营人员。生活事项可以进入同一个收件入口，但首版不围绕家庭协作或复杂日程管理展开。

### 3.2 核心用户需求

> 当新事情打断我时，我希望用很小的操作成本收下新事项、保存当前进度，并在合适的时候回到未完成的工作，让我不用一直靠脑子记着所有事情。

### 3.3 典型场景

| 编号 | 场景 | 用户期望 |
| --- | --- | --- |
| S01 | 写代码时，同事提出一个稍后处理的请求 | 快速记录，继续当前工作 |
| S02 | 排查问题时，线上故障需要立即处理 | 迅速切换，保留原任务及可选断点 |
| S03 | 连续处理几件临时事务后，暂时空下来 | 看见先前暂停的任务及下一步 |
| S04 | 工作需要等待同事反馈 | 标记等待，继续其他工作，回顾时仍能看见 |
| S05 | 临时关闭应用或重启电脑后继续工作 | 找回上次当前任务、暂停事项和已保存断点 |
| S06 | 下班前整理一天的工作 | 确认剩余事项，选好下一次开工的第一件事 |

## 4. 产品目标与成功标准

### 4.1 产品目标

- 新事项可以低成本被记录，不强迫用户立即分类或排期。
- 每个暂停任务都有明确去向，用户能找到它。
- 任务恢复时能同时看到任务名称、最近进展和下一步。
- 提示集中在用户主动操作的节点，避免新增持续打断。
- 应用关闭或重启不会清空已保存的工作状态。

### 4.2 MVP 效果验证

以下为试用阶段的建议验证口径，不属于已经取得的效果。首轮建议连续试用 5 个工作日；小样本只用于发现问题。

| 指标 | 口径与验证方式 | 判断方向 |
| --- | --- | --- |
| 快速记录成本 | 在给定简短任务标题的测试中，记录从唤起入口到保存完成的耗时和操作步骤 | 操作顺畅，不要求先填写其他字段 |
| 暂停任务遗忘 | 每日回顾时，由用户指出已经忘记但仍需要处理的事项，并与使用前自述对照 | 遗忘减少 |
| 任务恢复成本 | 对有断点和无断点的典型任务，询问恢复时是否需要重新查找、重新回忆 | 查找与回忆成本降低 |
| 断点使用意愿 | 观察切换时填写断点或跳过的原因 | 断点有用且记录负担可接受 |
| 提示干扰 | 收集用户认为多余、打断或重复的提示 | 不增加明显干扰 |
| 信任感 | 询问“现在是否还需要靠脑子记着全部未完成事项” | 记忆负担降低 |

具体数值门槛需在原型试用后确定。产品效果可通过访谈和本地观察验证，MVP 不以接入远程行为分析为前提。

## 6. 体验原则与信息架构

### 6.1 体验原则

1. **先收下**：任务标题即可完成创建。
2. **可以跳过**：紧急切换时，断点填写不构成阻塞。
3. **恢复有依据**：每次建议继续任务，都展示最近保存的上下文。
4. **决定权在用户**：不自动开始、切换、完成或取消任务。
5. **安静可控**：默认不周期弹窗、不播放提醒音；入口可隐藏。
6. **状态可信**：保存成功的内容可恢复，保存失败会明确告知。

### 6.2 产品界面

| 界面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 轻量桌面入口 | 当前任务名称、下一步摘要、暂停数量、待处理数量 | 记一件事、切换、完成、打开主窗口 |
| 快速记录框 | 单行标题，可展开备注 | 稍后处理、现在处理、关闭 |
| 主窗口 | 当前任务、待处理、已暂停、等待中、已结束 | 查看、开始、继续、修改状态 |
| 任务详情 | 标题、备注、断点记录、状态及相关时间 | 编辑、保存断点、继续、完成、取消 |
| 切换界面 | 当前任务、新目标任务、可选断点输入 | 保存并切换、跳过并切换、返回 |
| 恢复区域 | 推荐暂停任务及其最近断点 | 继续这件事、选择其他、暂不开始 |
| 收尾页面 | 当天完成、暂停、等待、待处理及下一次开工选择 | 确认保留、结束事项、选择首件任务、结束收尾 |
| 设置 | 快捷键、桌面入口显示、开机启动开关 | 调整偏好 |

“已结束”下区分已完成和已取消，避免把取消的任务计入完成结果。列表数量只统计对应状态中的任务，不累计已结束事项。

### 6.3 当前任务入口示意

```text
接着 PickUp

正在做：排查接口超时
下一步：检查客户端重试配置

已暂停 2 件 · 待处理 3 件

[记一件事]  [切换]  [完成]
```

以上仅表达信息层级，视觉样式和窗口尺寸由后续交互设计确定。

## 7. 任务模型与状态规则

### 7.1 最小任务信息

| 信息 | 是否必填 | 说明 |
| --- | --- | --- |
| 唯一标识 | 系统生成 | 用于区分同名任务，标题可以重复 |
| 标题 | 是 | 用户对事项的一句话描述；首尾空白不计入内容 |
| 状态 | 是 | 创建时默认待处理 |
| 备注 | 否 | 补充说明，可粘贴链接和文件路径 |
| 断点记录 | 否 | 包含进展、下一步和可选参考文本，可多次保存 |
| 创建、更新、状态变更时间 | 系统记录 | 支持排序、恢复与收尾展示 |
| 完成或取消时间 | 对应操作时记录 | 用于已结束列表和当日收尾 |

单条断点允许只写一句话；用户需要时再展开“已做进展”和“下一步”。每次显式保存形成一条带时间的记录，详情可查看历史，最新有效记录用于恢复提示。空白提交不覆盖已有断点。

“下一次开工第一件事”为全局可选任务引用，不是新的任务状态；同时最多选择一件未结束任务。

### 7.2 状态定义

| 状态 | 含义 | 进入方式 |
| --- | --- | --- |
| 待处理 | 已收下，尚未开始 | 快速记录、重新打开已结束事项 |
| 进行中 | 用户当前明确选择处理的任务 | 开始或继续 |
| 已暂停 | 做过一部分，当前暂时放下 | 暂停或切换到其他任务 |
| 等待中 | 推进依赖外部条件 | 用户主动标记等待 |
| 已完成 | 用户确认事情已经结束 | 完成 |
| 已取消 | 用户确认无需继续 | 取消事项 |

### 7.3 状态转换

| 当前状态 | 操作 | 目标状态 | 规则 |
| --- | --- | --- | --- |
| 待处理／已暂停／等待中 | 开始或继续 | 进行中 | 如已有当前任务，必须走切换流程 |
| 进行中 | 暂停 | 已暂停 | 可保存断点，允许跳过；允许暂不选择下一任务 |
| 进行中 | 切换到另一任务 | 已暂停 | 原任务暂停与目标任务开始作为一次完整切换 |
| 待处理／进行中／已暂停 | 等待他人或条件 | 等待中 | 等待原因选填；原任务是当前任务时清空当前位 |
| 等待中 | 条件已满足，稍后处理 | 待处理 | 保留断点和原有记录 |
| 任意未结束状态 | 完成 | 已完成 | 不要求先开始；完成后保留全部记录 |
| 任意未结束状态 | 取消事项 | 已取消 | 与关闭输入框区分，操作后可重新打开 |
| 已完成／已取消 | 重新打开 | 待处理 | 保留历史，清除当前有效结束状态；不自动抢占当前任务 |

约束：

- 同一时刻最多一件任务处于进行中，也允许没有当前任务。
- 创建、查看、修改备注、选择明日事项均不自动开始任务。
- “继续”保留此前断点，直到用户保存新的记录。
- 等待中任务不作为默认恢复推荐，用户可主动选择。
- 本版以取消和重新打开处理误建或放弃事项，不提供不可恢复的单任务删除操作。
- 日期变化不修改任务状态，不清空断点，不自动完成或暂停当前任务。

## 8. 功能需求与验收标准

### F01 快速记录

**用户故事**：作为正在处理任务的用户，我希望随手记下新事项，随后回到原工作。

功能规则：

- 支持从桌面入口、主窗口和全局快捷键打开记录框，打开后输入焦点在标题。
- 标题为唯一必填项；备注按需展开。
- Enter 默认保存为待处理；“现在处理”须明确选择。
- 保存成功后关闭记录框，尽可能返回唤起前的工作界面。
- Esc 或关闭窗口不创建任务；未提交文字保留为草稿，下次唤起可继续或主动清空。
- 相同标题可以分别保存；同一次提交的重复按键不得产生重复记录。

验收标准：

- **AC-F01-01**：已有 A 进行中，输入 B 并按 Enter 后，B 为待处理，A 仍为进行中。
- **AC-F01-02**：空标题或全空白标题不能提交，提示出现在输入处。
- **AC-F01-03**：仅填写有效标题即可保存，不要求项目、日期或分类。
- **AC-F01-04**：关闭含未提交文字的记录框后重新唤起，草稿仍可继续编辑。
- **AC-F01-05**：保存过程中连续按 Enter，当前提交只创建一件任务。

### F02 当前任务与桌面入口

**用户故事**：作为被频繁打断的用户，我希望快速确认自己现在主要在做什么。

功能规则：

- 展示当前任务标题、最近断点中的下一步摘要和未结束事项数量。
- 没有当前任务时展示“现在准备做什么”，提供选择任务和快速记录入口。
- 桌面入口可移动、收起或隐藏，状态和位置在重启后保留。
- 开启桌面入口不应阻挡正常操作；默认不强制置顶，置顶作为用户可控偏好。
- 当前任务、列表和详情中的状态保持一致。

验收标准：

- **AC-F02-01**：A 切换为 B 后，桌面入口和主窗口均显示 B。
- **AC-F02-02**：无进行中任务时不展示上一件任务为“正在做”。
- **AC-F02-03**：隐藏桌面入口后仍可通过主窗口或快捷键访问产品。
- **AC-F02-04**：长标题和长断点可截断展示，用户能够打开详情查看完整内容。

### F03 保存断点与任务切换

**用户故事**：作为必须处理紧急事项的用户，我希望先留下原任务的恢复线索，再开始新任务。

功能规则：

- 从 A 切换到 B 时，展示可选断点输入及 A 最近的断点供参考。
- 主操作为“保存并切换”，另有清晰的“跳过并切换”。
- 用户可以只记录下一步，也可以补充进展与参考文本。
- 无当前任务时，开始 B 无需经过断点界面。
- 从快速记录选择“现在处理”时，先保存 B；如用户返回或关闭切换界面，B 保持待处理，A 保持进行中。
- 从列表切换时，关闭切换界面不会改变任何任务状态。
- 切换保存失败时保留输入和原状态，不展示切换成功。

验收标准：

- **AC-F03-01**：A 进行中时选择 B，保存一句断点后，A 变为已暂停，B 变为进行中，A 的详情能找到该断点。
- **AC-F03-02**：选择跳过后可立即切换，A 的已有断点保持不变；没有断点则标明“尚未记录断点”。
- **AC-F03-03**：取消切换后，当前任务仍为 A；快速新建的 B 已保存在待处理列表。
- **AC-F03-04**：模拟保存失败后，界面保持 A 为当前任务，断点输入可重试，不出现两件进行中任务。
- **AC-F03-05**：再次选择当前任务 A 不触发自我暂停或重复开始。

### F04 完成与恢复

**用户故事**：作为处理完临时事项的用户，我希望立即看见之前放下的工作，并知道怎样接着做。

功能规则：

- 点击完成后更新任务状态；若完成的是当前任务，清空当前位并展示恢复区域。
- 默认推荐最近暂停的一件任务，并提供其他暂停事项入口；相同时间时用稳定顺序展示。
- 推荐展示任务标题、最近断点和暂停时间；无断点时允许直接继续。
- 无暂停任务时展示待处理入口；两者均为空时展示空状态。
- 用户可选择继续、选择其他或暂不开始；推荐本身不改变状态。
- 完成非当前任务时，不中断当前任务，也不强制弹出恢复区域。
- 误完成可通过结果提示或已结束列表重新打开，恢复为待处理。

验收标准：

- **AC-F04-01**：A 暂停后开始 B，完成 B 时可看到 A 及其断点；点击继续后 A 为进行中。
- **AC-F04-02**：A、B 先后暂停，完成 C 时优先推荐 B，用户也能选择 A。
- **AC-F04-03**：选择“暂不开始”后当前位为空，所有暂停任务保持原状态。
- **AC-F04-04**：仅有等待中事项时，不自动将等待事项设为当前任务。
- **AC-F04-05**：重新打开误完成任务后，它回到待处理并保留断点，其他当前任务不受影响。

### F05 任务整理与等待

**用户故事**：作为同时处理多个事项的用户，我希望区分尚未开始、暂时放下以及等待外部条件的事情。

功能规则：

- 按状态查看任务；待处理默认按创建时间从早到晚，暂停和等待默认按进入该状态的时间从近到远，已结束按结束时间从近到远。
- 可编辑标题、备注，保存修改后不改变任务状态。
- 标记等待时可填写“等谁／等什么”，不要求填写到期时间。
- 等待事项持续保留在列表和收尾页面，直到用户主动更新。
- 将当前任务标为等待、暂停、完成或取消后，允许选择下一任务或保持空闲。
- 取消事项使用明确文案“取消这件事”，关闭窗口使用“关闭”或“返回”。

验收标准：

- **AC-F05-01**：A 标记为等待并填写原因后，可在等待列表查看原因及原断点。
- **AC-F05-02**：等待条件满足后可转为待处理；选择立即继续且已有 B 进行中时，进入 B 的切换流程。
- **AC-F05-03**：编辑任务标题后，桌面入口、详情、列表中的标题一致。
- **AC-F05-04**：取消任务后不再计入未结束数量；重新打开后恢复为待处理。

### F06 每日收尾与下次开工

**用户故事**：作为准备结束工作一天的用户，我希望确认剩余事项有去处，并为下一次开始留下入口。

功能规则：

- MVP 由用户主动进入“今日收尾”，不默认设置定时通知。
- 按设备本地日期展示当天完成的任务，以及当前所有暂停、等待、待处理事项；如有进行中任务，置于显著位置。
- 各项数量均对应可打开的实际任务，不只展示统计数字。
- 用户可以保留事项、标记完成、取消、补断点，并选一件未结束事项作为下一次开工第一件事。
- 如仍有进行中任务，结束收尾时提供“暂停并结束”和“保留当前状态”两个明确选择；断点填写仍可跳过。
- 选择下次第一件事不会改变其状态；下次启动展示该选择。如仍有当前任务，开始所选事项需正常切换。
- 所选事项后来完成或取消时，清除失效选择，不展示已结束事项为待开工任务。
- 重复进入收尾不创建任务副本，不清空尚未处理的事项。

验收标准：

- **AC-F06-01**：收尾页面能够访问跨日遗留的暂停和等待事项。
- **AC-F06-02**：选好下次第一件事并重启后，该选择仍存在；未点击开始前不变为进行中。
- **AC-F06-03**：结束收尾并选择暂停后，原当前任务进入已暂停，其断点可恢复。
- **AC-F06-04**：选择保留当前状态后，结束收尾不会自动暂停当前任务。
- **AC-F06-05**：跨越午夜后，任务状态和断点保持不变，当天完成列表按新日期重新计算。

### F07 保存、恢复与基本设置

**用户故事**：作为依赖应用记住工作的用户，我希望重启后仍能找到已确认保存的任务和进展。

功能规则：

- 本版建议采用本地数据保存，无账号前置要求；任务正文和断点无需上传即可完成核心流程。
- 只有在任务及相关状态保存成功后才呈现成功结果。
- 启动时恢复任务、最新有效状态、断点历史、下次开工选择与界面偏好。
- 关闭主窗口不自动改变任务状态；后台可用时保留快捷入口，完全退出时快捷唤起不可用，下次启动恢复状态。
- 提供完全退出入口；开机启动默认关闭，由用户主动开启。
- 全局快捷键可修改；冲突时明确提示，并保留主窗口入口。
- 多次启动不得造成并行修改导致的数据覆盖；实现方式由技术设计决定。
- 保存失败时说明未保存，保留用户输入并允许重试；不静默丢弃或清空数据。

验收标准：

- **AC-F07-01**：创建 A、保存断点、切换到 B 后退出并重启，A、B 状态和断点与已确认保存的结果一致。
- **AC-F07-02**：模拟异常退出后，已确认保存的任务和断点可恢复；未确认保存的内容不宣称恢复保证。
- **AC-F07-03**：模拟持久化失败时，无虚假成功提示，输入可继续编辑或重试。
- **AC-F07-04**：快捷键冲突时用户可更换组合，且仍能从应用入口打开记录框。
- **AC-F07-05**：重复启动应用后仍只有一套一致的任务状态，不出现重复任务或覆盖已保存内容。

## 9. 完整业务流程示例

### 9.1 连续打断后恢复

1. 用户开始 A“排查接口超时”，A 为进行中。
2. 同事提出 B“查询昨日订单数据”，用户快速记录，B 为待处理，A 不变。
3. 收到 C“处理线上故障”，用户选择现在处理。
4. 用户为 A 留下断点：“已排除数据库慢查询；下一步检查下游重试配置。”
5. 保存后 A 为已暂停，C 为进行中，B 仍为待处理。
6. 用户完成 C，系统推荐恢复 A，并展示第 4 步的断点。
7. 用户选择继续 A，A 为进行中；如果决定先处理 B，可以主动选择 B，A 保持已暂停。
8. 收尾时，所有未结束事项仍可见，用户决定下次从哪件事开始。

### 9.2 紧急切换与等待反馈

1. A 进行中时出现 B，用户跳过断点直接切换，A 仍被保留为已暂停。
2. B 需要同事反馈，用户标记等待并记录等待原因，当前位清空。
3. 用户主动恢复 A；若 A 没有断点，仍可打开任务备注并继续。
4. B 不主动弹窗；用户查看等待列表或收尾页面时可以再次看到它。
5. 收到反馈后，用户把 B 放回待处理，或通过正常切换流程立即继续。

## 10. 异常与边界情况

| 情况 | 预期行为 |
| --- | --- |
| 首次使用，无任何任务 | 展示简短引导和“记下第一件事”，不强迫完成复杂配置 |
| 同名任务 | 允许存在，通过备注、时间和唯一标识区分 |
| 标题很长或含多语言文字 | 可正常保存；摘要不撑破布局，详情可查看完整内容 |
| 断点为空 | 不阻塞切换，不覆盖历史，不虚构进度 |
| 切换中途关闭窗口 | 原当前状态不变，已创建的新事项留在待处理 |
| 连续多次切换 | 所有暂停事项保留，推荐排序稳定，没有事项被挤出列表 |
| 重复点击完成或切换 | 同一操作不会创建重复记录或产生矛盾状态 |
| 修改或完成下次开工事项 | 名称更新同步；已结束时清除失效引用 |
| 恢复目标状态已变化 | 按最新状态更新界面，不根据旧界面错误开始任务 |
| 多显示器环境变化 | 桌面入口回到可见屏幕区域，避免保存位置导致找不到窗口 |
| 设备日期或时区变化 | 当前任务状态不变；每日视图按设备本地日期解释，历史记录保留 |
| 本地保存失败 | 保留输入、明确提示、可重试；不得静默覆盖历史 |

## 11. 非功能需求

### 11.1 响应与资源

以下为建议工程验收目标，需在确定的支持设备与数据规模上测量：

- 应用已运行时，快捷唤起到输入框可输入的耗时，95% 样本不超过 500 毫秒。
- 常规本地保存与状态切换在正常环境下 95% 样本不超过 1 秒；超时应显示可理解的进行中状态。
- 建议以累计 1,000 件任务、每件最多 10 条短文本断点作为首轮性能验证规模，核心操作满足上述目标。
- 空闲状态不持续运行高频轮询或产生周期提示。内存、CPU 和安装包目标在技术方案明确后补充。

### 11.2 可用性与可访问性

- 快速记录、保存、关闭和主要切换操作支持键盘操作，焦点顺序明确。
- 输入状态、选中状态、保存失败和任务状态不只通过颜色区分。
- 在目标系统常见显示缩放下，关键按钮、标题和输入框可用。
- 中文为首版界面语言建议；允许任务内容使用中英文混合输入。
- 关闭窗口、取消切换、取消事项的文案与后果应清楚区分。

### 11.3 数据与隐私

- 核心功能在离线环境可用。
- 默认不采集任务正文、断点、屏幕、剪贴板或聊天内容；用户主动粘贴属于显式输入。
- 如后续增加远程诊断、同步或第三方集成，需另行定义数据范围与用户控制方式。
- 本地持久化不等同于备份；设备损坏与数据迁移保障不在本版承诺内，数据导出和备份列为后续候选。

## 12. 验收与试用计划

### 12.1 MVP 发布前验收

P0 功能及其验收标准全部通过，重点完成以下端到端检查：

1. A 进行中 → 收下 B → A 保持进行中。
2. A 进行中 → 保存断点 → 切换 C → 完成 C → 恢复 A。
3. A 进行中 → 紧急跳过 → B 进行中 → B 等待 → 恢复 A。
4. 多次切换 → 退出并重启 → 所有状态和已保存断点一致。
5. 收尾 → 选择下次第一件事 → 重启展示 → 用户主动开始。
6. 误完成 → 重新打开 → 原断点保留，其他当前任务不受影响。
7. 保存失败 → 保留输入与一致状态 → 重试成功。

数据丢失、两件任务同时进行中、完成后任务消失且无法找回、后台持续干扰用户等问题应阻断发布。

### 12.2 用户试用

建议邀请最初提出需求的用户先完成 5 个工作日试用，记录：哪些新事项没有被记下、哪些切换跳过了断点、哪些恢复提示有帮助，以及哪些操作增加了负担。优先据此调整交互，再决定扩展功能。

## 13. 风险与应对

| 风险 | 对产品的影响 | 本版应对 |
| --- | --- | --- |
| 记录动作太重 | 用户直接跳过，工具中的状态逐渐失真 | 标题即可创建；一句断点即可保存；紧急可跳过 |
| 用户忘记打开应用 | 记录不完整 | 快捷入口、可选桌面入口、可选开机启动 |
| 暂停事项持续堆积 | 恢复列表失去可读性 | 当前任务突出、按状态查看、收尾时主动结束不再需要的事项 |
| 恢复建议不符合真实优先级 | 用户被错误引导 | 展示推荐依据，始终允许选择其他或暂不开始 |
| 断点记录不够有用 | 恢复时仍需重新回忆 | 引导填写“下一步做什么”，通过试用验证实际价值 |
| 保存不可靠 | 用户失去对工具的信任 | 明确保存结果、异常恢复和失败重试作为 P0 |
| 团队要求所有事项立即处理 | 工具无法创造连续工作时间 | 提供清楚的任务状态，为用户协调工作提供依据 |

## 14. 待确认事项与后续产出

| 待确认项 | 当前建议 | 影响 |
| --- | --- | --- |
| 首发系统与最低版本 | 先做 Windows，具体最低版本由技术评估明确 | 打包、快捷键、窗口行为和测试范围 |

| 数据导出是否需提前 | 目前列为 P1，正式长期使用前复核 | 数据可携带性和备份需求 |
| 断点输入负担 | 一句话即可，结构化字段按需展开 | 核心功能使用率 |
| 生活场景优先级 | 首版允许记录，手机端后续评估 | 平台范围与体验设计 |
| 性能目标与验收环境 | 采用第 11 节建议值，技术评审时确认设备基线 | 可执行的性能测试条件 |
